## 状态语义

本周目模式使用当前开箱位；继承记录模式使用“当前开箱位或继承位”。新开的箱子因此立即进入两组计数。
每次读取存档都以游戏当前状态为准，不在 Mod 中维护独立的累计历史。
两组全局和地区统计来自同一份快照，面板每 250 毫秒刷新，原生地图图标在调用时读取状态。

目录生成器保留宝箱表原始行号，应用游戏定义的覆盖标志规则，排除开发地图记录。
每个正式目标只属于一个统计地图。相邻道路拆开统计，迷宫按场景汇总各楼层；
大地图前缀负责定位，显示模式不改变地图归属。

## 版本与地图挂钩

挂钩前检查 EXE 完整哈希和内存中的预期指令或虚表目标，冲突时不覆盖未知挂钩。
原生区域地图采用表驱动的图标函数，对象图标路径另行兼容。位置、缩放和区域布局由游戏负责。
面板初始化失败时不启用地图修改，防止玩家无法辨认当前显示模式。

所有 RVA 仅针对 README 指定的 EXE。适配新版不能只修改哈希；需要重新验证函数、对象布局和标志语义。
DLL 不直接写宝箱状态或游戏存档，也不替玩家触发成就；原生传送、行走和开箱仍可推进剧情并触发自动保存。

## 可选探索辅助

两个功能启动时均关闭。地图全显仅在已验证的分块调用点改写
传给原生材质递归函数的 alpha，仍采用所属楼层的淡入淡出数值并尊重脚本禁用分块。
不改探索区块字段或保存记录；关闭后由下一次原生绘制恢复真实探索状态。

“未到访传送点”按原生传送菜单许可统一判定，不维护目的地 ID 白名单或固定点位数量。
在原生地图显示构建前自动枚举当前地区的传送状态，
要求最终 `registered && !blocked`；有所属 area 时，该分组也必须属于当前地区且最终未被禁用。
满足条件的未到访点可临时显示，必要时同时显示 area 分组，不要求真实到访锚点或该分组此前已经发现。
检查基于已经完成的原生状态脚本结果，不把登记期间尚未施加灰态的中间状态视为最终许可。
只接受三个已经确认先执行状态脚本的原生调用来源，以及即时刷新中精确包围本次显示构建的线程局部许可。
场景初始化及未知调用来源保持原生行为，不能把尚未重新计算的缓存当作当前剧情许可。
重复、未知或不一致的数据不处理；点及分组只临时改变菜单缓存中的可见状态，不写真实到访旗标。
游戏后续的静态条件、内部点和特殊标识过滤仍参与构建，已登记并不保证最终一定有玩家可选项目。
不解除原生最终灰态，不扩大当前地区枚举范围，保留原生确认及传送前后脚本。
这一语义不等于完整剧情可达判断：真实到访限制、物理门锁及事件入口之间没有统一的无副作用判定，
因此显示出来的未到访点可能越过入口剧情、物理障碍或迷宫层级。
地图重建后重新计算，不保留自己的到访历史。
实际行走和传送仍可能按游戏机制产生真实进度。

绘制／输入线程只提交传送开关请求，不从 `Present` 调用游戏脚本或操作原生菜单对象。
原生区域地图、全地点列表与城镇子列表的安全浏览调用链消费刷新请求，重新生成菜单状态与列表；
同一次刷新使用固定的目标开关，连续切换时以后续最新请求为准。确认窗口、地图转场等阶段先保留请求，
返回浏览阶段后自动应用，面板区分请求状态与已应用状态。

刷新保留地图镜头和缩放；若原选中项因关闭辅助而消失，使用原生逻辑重新选取有效地点，
避免留下可确认的旧选项。列表滚动位置可能回到默认值。此流程仍需要按游戏内测试清单验证，
纯逻辑测试不能证明所有菜单状态和剧情组合都已覆盖。
重算后，当前子列表或完整传送清单可以合法为空。适配层区分空清单与结构校验失败，
在调用会读取第一个项目的原生列表构建函数之前，改用原生状态 17 的退出动画关闭地图；
此时保持功能可用，不执行传送，也不在菜单更新调用栈内销毁菜单对象。
普通地图浏览可以从空显示数组开始处理开关；地点列表和子列表则仍要求原列表有效且非空。

原生编译器对内部调用采用了比标准 x64 ABI 更强的寄存器保留假设。
地图参数桥保存所有易失寄存器，仅替换 XMM3 的低 32 位；传送显示构建及菜单浏览桥在原函数之前执行辅助逻辑，
恢复全部易失寄存器、XMM0～5、RFLAGS 与原始参数后，再进入原生函数。
Windows 回归测试直接链接生产汇编，故意破坏辅助回调的寄存器，核对传参、返回态、栈对齐和边界。
功能入口冲突会停用对应辅助，并通过面板和日志报告，不覆盖未知挂钩。

适用范围与待验证项目见 [探索辅助测试指南](EXPLORATION_TESTING.md)。

## 全传送与精确返程

当前版本为 `0.5.0`，默认提供全传送。原生表保留 180 条记录、166 个唯一 ID；展示层保留 155 个原生地点，另加迷途之森补箱入口与精确返程，共 157 项、16 页。11 个纯内部 ID 隐藏。没有预览图的正常命名地点不因此被删除，同一个公开 ID 的南口、北口等内部变体也不等于独立内部目的地。

ID 136～143 的四塔入口／最深处显示完整“异空间”名称，ID 146 显示为“旧校舍地下遗迹 / 入口”。展示别名不改变原生 ID、落点或加载流程；两份清单共用翻页操作，并分别保留进程内导航位置。

`tools/extract_travel_catalog.py` 生成真实目录，`revisit_catalog.h` 负责展示和分页，`revisit_native.cpp` 核对原生身份并在游戏线程消费请求。无游戏资源的公开测试使用目录替身；替身不能用于发布 DLL。

### 全传送与剧情限制策略

`revisit_policy.h` 通过编译选项 `SKY2_UNRESTRICTED_TRAVEL` 分离两种策略，CMake 默认 `ON`、头文件宏默认 `1`。正式 DLL 使用全传送；开发者可显式构建剧情限制策略作对照，没有运行时快捷键切换。已有保守测试显式定义宏 `0`，全传送测试显式定义 `1`，不随 DLL 默认值变化。

| 校验 | 全传送，正式默认 | 剧情限制，开发对照 |
| --- | --- | --- |
| 普通地点登记、目的地和 area 禁用 | 不作为目的地准入条件 | 要求本次原生规则允许 |
| 已审查旧图的章节与完成旗标 | 不作为目的地准入条件 | 分组复核原有门槛 |
| `MapJumpCallScript` 活跃前置分支 | 不以此拒绝出发、目的地或返程 | 只读判断，尚需接管时拒绝 |
| 迷途之森章节与 20064／20067 完成条件 | 不作为入口准入条件 | 必须满足 |
| 11 个纯内部 ID | 隐藏并拒绝 | 隐藏并拒绝 |
| 真实身份、坐标、菜单稳态、二次确认、记录和保护模块 | 必须通过 | 必须通过 |

两种策略都仅接受原生章节 0～9 的有效自由行动上下文。剧情限制策略读取本次 `MapJumpState` 已结束的 spot／area 数组，要求 `registered && !blocked`，分组存在且未禁用；允许未到访点，不把当前显示地区当成全目录范围。该策略的 25 个旧图落点和克雷德尔分别复核已审核的晚期完成门槛，荣耀号补箱例外仅在第 9 章相关剧情完成时开放；前期正常主线场景的地理身份和晚期补箱门槛分别处理。

剧情限制策略通过 `revisit_phase_rules.h` 只读复核各章节前置分支，不执行有副作用的脚本试探许可。早期返程按记录目标的场景和地点匹配可能入口，不能以当前出发点预检代替返程目标验证。无独立传送点的合法道路使用明确的默认目标规则，不把指定入口的局部限制扩大到全部道路。旗标 1073 也进入短期请求摘要。

全传送取消的是上述目的地剧情准入。它不执行其他章节脚本来伪造许可，不补写剧情完成或到访位，也不声称已走完被越过的前置脚本。原生场景初始化、事件、互动和自动保存仍会运行，所以传送本身成功并不证明目标剧情适合当前进度。这里的编译开关不改变“未到访传送点”探索开关的菜单补显规则。

### 地点身份与原生加载

同 ID 变体按原生当前地形标识优先选择，无匹配时遵循原生首条回退；菜单显示地区、菜单 place 与实际加载 scene 不能混为一体。12 个公开跨图 ID 的菜单 place 属于出发／展示场景，原生加载使用另一 scene 及其坐标。全传送仍逐项核对原始行，并按真实目标 scene 的唯一默认根地点确定到达地区；这属于原表的正常跨图表示，不能报告成缺少资源，也不能任取最近地点替代。

捕获当前身份时同时核对主地点和当前脚下地形的真实 `t_place` 记录。记录中的 variant 只描述当前地形，主地点可使用不同标识；根候选有歧义或当前地形不匹配均拒绝。荣耀号的主地点地区 7／8、楼层地区 0，只在精确场景、变体和原表关系满足时归一；地区 0 本身不是通行证。

迷途之森使用独立 Mod 哨兵，严格核对 `mp0081`、place 1008100、variant 0，以及原生剧情收尾后的自由行动坐标 `(0, 0, 0)`、朝向 0。它没有原生传送点、只有一个宝箱、没有普通出口；原生底图只有简略矩形，必须另行验证记录返程。市政府同样没有独立原生点，沿克雷德尔入口步行前往，不虚构市政府落点。

所有请求都从稳定原生区域地图浏览链消费，不从 Present 线程执行游戏函数。非自由行动、战斗、对话、演出、加载、身份或坐标无效时仍不能提交。原生桥写入经过核对的菜单退出结果，经退出动画、对象销毁及外层消费者调用正常加载；精确返程恢复记录中的坐标与朝向，仍走原生初始化和到达脚本。

### 最初出发点与会话

`revisit.cpp` 在首次出发前通过 `revisit_return_point.h` 捕获场景、地区、当前地形标识、坐标、朝向和章节，再由 journal 模块写入：

```text
Sky2ChestTracker/
├─ revisit-return.dat
└─ revisit-history/<记录编号>.dat
```

文件包含格式版本、游戏构建标识、长度和校验码，历史票据不覆盖。使用同目录临时文件、刷新及替换；持久化失败拒绝新的出发。它们不是游戏存档，不保存队伍、物品或任务，也不承担进度回滚。安装更新、卸载和手动回退均应保留这些文件。

首次出发要求 `returnPointReady`，真正保存前再次核对身份和时效。连续传送或步行离开旧图始终保留最初点；精确返程确认到达后才结束行程。明确切换到另一合法章节时结束旧活动会话，加载中的无效快照和同章正常开箱不清除它。记录中的剧情摘要只供诊断，不是持久兼容条件；短期请求仍使用当前摘要取消陈旧操作。

章节、剧情摘要、历史文件和内存地址都不能证明存档栏位身份。重启只能让玩家核对地点、章节、时间并二次确认历史返程，不能据此恢复行程保护或自动传送。同进程同章切档无法可靠识别，可能遗留上一档的活动点及行程状态，因此应先返程或退出重启再切档。已有历史的第 8／9 章旧图重启仍先核对返程记录，不能把旧图站位覆盖成新的最初点。

兼容已有第 8 章序章无返程记录的柏斯应急出口时，剧情限制策略保留免记录路径；全传送策略必须先捕获当前位置并持久保存新的活动出发点，记录失败则拒绝派发。此兼容分支不提供任意存档的通用退出保证。

### 保护范围与行程边界

`revisit_event_guard.cpp` 只识别唯一的原生 `TBoxProcess` 调用点，严格核对表行、场景、对象与参数，将六个序章特殊箱和一个荣耀号特殊箱的临时参数改为普通开箱参数。`revisit_forest.cpp` 在原生事件盒启用 builtin 中仅过滤 40 个已审核的森林谜题名称，改写本次启用参数；不批量禁用场景脚本、声音、NPC 或普通宝箱。

剧情完成条件满足时，原有章节保护独立生效。全传送只有在最终消费者完整校验通过、即将执行本次 Mod 出发时，才启用内存中的行程许可，让这 7 个箱和 40 个事件盒在未达到原有章节门槛时使用限定保护。精确返程调用原生加载器前先关闭该许可，避免回到正常主线森林时误禁应执行的谜题；返回失败按实际提交结果处理，不能把旧许可泄漏到新行程。

行程许可绑定本次原生章节令牌。保护模块回调和原生上下文读取均核对真实章节，发现另一合法章节便以原子比较交换使令牌失效；不依赖窗口是否显示或协调层能否及时刷新，读回旧章不会复活。协调层也会在安装、换章和确认返程等相应节点清理。

该许可不写入 journal，重启不按相同章节或历史记录重建；原有完成门槛保护仍独立判断。启动后直接读入旧地图存档不等于正在进行一趟新的 Mod 传送行程，原生事件可能恢复，不能承诺读档后所有旧剧情仍被抑制。

这些局部保护不是全局剧情防护。其他场景事件、走动、开箱、战斗或互动仍可能推进剧情，原生奖励、宝箱记录、淡入淡出和自动保存继续执行。回退 DLL 或源码不会撤销这些存档变化。

### 输入、到达与验证

传送选择和宝箱页码是彼此独立的进程内 UI 状态。传送清单首次打开沿用原有初始化规则：需要恢复返程的场景优先选择返程，否则选择第一项；初始化后，单纯关闭清单、隐藏主面板或切换到另一份清单不重新选择。再次打开恢复原目的地及其所在页，不依当前场景反复跳回默认项。

宝箱计数快照暂时无效时不收缩页码，数据有效后按实际页数校正；条目减少或分辨率、布局变化导致越界时，调整到最后有效页。显示模式或遗漏筛选会改变列表内容，仍主动回到第一页。两份清单的导航状态不写入 journal、配置文件或游戏存档，重启清除；不新增不可靠的同章读档检测，也不保证读档必然重置清单位置。

`Ctrl + F10`／`View + 十字键左` 打开窗口。传送与宝箱清单统一使用 `PgUp`／`PgDn`、`View + LB`／`View + RB` 翻页；每次只翻相邻一页，尽量保留页内所选行，末页截到最后有效项，首末页不循环。传送逐项选择使用 `Ctrl + PgUp`／`Ctrl + PgDn`、`View + LT`／`View + RT`，每次移动一个相邻项，可在页边界自动换页。同帧翻页与逐项移动只执行前者，传送窗口收起时逐项组合不影响宝箱清单。

扳机逐项输入采用独立按下沿与释放滞回：按下阈值大于 30，释放阈值小于等于 15；View 外也维护状态，避免抖动、长按或预按造成重复选择。翻页键同样不因长按连续翻页。

`Ctrl + F7`／`View + 十字键右` 两次独立按下才确认；精确返程行用 `F10`／`View + Y` 切换历史。确认八秒失效，排队五秒失效，场景、选择、菜单身份或短期摘要变化都会取消，两种策略均保留这些规则。关闭、隐藏或导航仍取消二次确认，重新显示原选中项不会恢复先前授权。

“已交给原生换图”和实际到达分开。普通目标核对真实加载场景，精确返程还核对站位；同场景短加载结合原生目标变化或实际位置证据，不仅依赖一次 busy 采样。超过 60 秒仍无到达证明时进入 `ArrivalUnconfirmed`，解除等待锁但保留活动出发点；超时不是到达成功。

验证分别运行全传送和剧情限制策略，覆盖身份拒绝、跨图目标、有限保护作用域、返程前关闭、重启不自动恢复，以及记录／ABI／输入边界。已获得二周目前期、一周目末期相关传送正常的反馈，不代表全部原生落点及章节组合均已验证。导航位置记忆和两列页脚按 [测试说明](TESTING.md) 回归；实际操作及功能边界见 [全传送指南](TRAVEL.md)。

## 面板提示与用语

宝箱状态统一使用“已开／未开”，差额统一为“剩余未开”，当前游玩轮次统一称为“本周目”。
图例、全局与地区计数、清单和快捷键说明使用相同用语；术语调整不改变位标志、统计或筛选语义。
快捷键与动作分列对齐；顶部选择项统一称为“显示模式”，切换动作称为“切换模式”。
探索行将名称与状态直接连接，例如“地图全显：已关闭”，不再为状态预留独立宽列。
对应组合键使用与宝箱快捷键一致的高亮颜色，并与上方右侧按键列对齐；键盘与手柄采用同一对齐规则。
主面板直接显示快捷键与动作。地图收集清单底部使用三列两行：第一行放置“切换模式”“全部/遗漏”“收起清单”，第二行放置“上一页”“下一页”。传送清单底部使用两列，按“上一页／下一页”“上一项／下一项”“确认／收起清单”逐行配对，需要选择历史返程记录时再显示对应按键；两列分别测量完整组合键宽度。
页码位于顶部“已完成 … 张地图／剩余未开 …”统计行的最右侧，与清单内容区右边缘对齐；等待游戏数据时不显示尚无依据的页码。
主面板宽度按实际文字及当前输入方式测量，减少固定宽度产生的右侧留白；测量仍需容纳两组地区计数、完整手柄组合、探索名称与状态，并保留按键列的对齐。
清单按最长地图路径、计数列、顶部统计与完整快捷键测量所需宽度，减少“大地图 / 地点”列的多余留白；可用窗口较窄时，保留长路径换行，不能仅为缩短列宽而截断地图名称。
每个操作单元分别绘制高亮按键与普通动作文字；手柄组合逐项带上 View 前缀，不依赖标题或共享缩写补全。宝箱清单、传送清单与主面板使用相同的按键高亮颜色，两份清单的全部按键提示均显示完整组合。
底部只保留一句简短说明；等待应用和功能不可用等状态使用同一提示区域，详细功能边界由文档说明。
布局仍跟随输入设备热切换，按键绑定和动作分发保持原有逻辑。

## 面板分辨率缩放

每帧读取交换链后缓冲尺寸，缩放比例取 `min(宽度 / 1920, 高度 / 1080)`。
面板继续使用逻辑坐标布局，ImGui 的 `DisplaySize` 设为实际尺寸除以比例，`DisplayFramebufferScale` 设为该比例。
项目固定版本的 DX11 后端同步缩放视口和裁剪区域，并按该密度生成字体，因此不必逐个修改面板尺寸与间距。
读取尺寸后立即释放后缓冲引用；分辨率切换时重新计算，不重复累乘样式数值。
该设置只影响 Mod 面板，游戏原生地图的位置和缩放仍由游戏负责。

## 手柄和设备切换

输入接入点在游戏自身的 XInputGetState 导入槽，继续调用原目标以保留 Steam Input 映射。
每个手柄槽独立维护状态。View 作为修饰键时，组合不传给游戏；先松开 View 后仍按住的功能键继续被屏蔽到真正释放。
单独 View 在松开时补发一次，并维护输出状态的数据包序号。

实际按键活动及死区外的有效模拟输入切换到手柄提示；键盘和真实鼠标消息切回键鼠提示。
后台不执行 Mod 动作，重连／回到前台需松开控制后重新进入可用状态。
Mod 不拦截系统全局快捷键，因此避开会与 Xbox 窗口冲突的 View + Menu，使用 View + RS 暂停。

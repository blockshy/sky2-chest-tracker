# 实现结构

## 模块

| 文件 | 职责 |
| --- | --- |
| `native/xinput_proxy.cpp` | 转发游戏导入的 XInput ordinal 2／3，启动后台初始化 |
| `native/tracker.cpp` | 校验 EXE、读取状态快照、接入原生地图图标选择函数 |
| `native/core.h` | 纯位标志读取和两种显示模式的图标语义 |
| `native/progress.h` | 同一快照内计算地图进度与遗漏筛选 |
| `native/overlay.cpp` | D3D11 Present 绘制、清单布局及动作分发 |
| `native/ui_scale.h` | 按实际后缓冲尺寸计算 1080p 基准缩放比例 |

| `native/exploration_logic.h` | 区块边界检查及原生登记／最终禁用状态的统一判定 |

| `native/controller_logic.h` | 手柄组合、松键保护、前台恢复和死区活动判断 |

## 状态语义

本周目模式使用当前开箱位；继承记录模式使用“当前开箱位或继承位”。新开的箱子因此立即进入两组计数。
每次读取存档都以游戏当前状态为准，不在 Mod 中维护独立的累计历史。
两组全局和地区统计来自同一份快照，面板每 250 毫秒刷新，原生地图图标在调用时读取状态。

目录生成器保留宝箱表原始行号，应用游戏定义的覆盖标志规则，排除开发地图记录。
每个正式目标只属于一个统计地图。相邻道路拆开统计，迷宫按场景汇总各楼层；
大地图前缀负责定位，显示模式不改变地图归属。

## 版本与地图挂钩

挂钩前检查 EXE 完整哈希和内存中的预期指令或虚表目标，冲突时不覆盖未知挂钩。
原生区域地图采用表驱动的图标函数，对象图标路径另行兼容。位置、缩放和区域布局由游戏负责。
面板初始化失败时不启用地图修改，防止玩家无法辨认当前显示模式。

所有 RVA 仅针对 README 指定的 EXE。适配新版不能只修改哈希；需要重新验证函数、对象布局和标志语义。
DLL 不写宝箱状态或存档，也不替玩家触发成就。

## 可选探索辅助

两个功能启动时均关闭。地图全显仅在已验证的分块调用点改写
传给原生材质递归函数的 alpha，仍采用所属楼层的淡入淡出数值并尊重脚本禁用分块。
不改探索区块字段或保存记录；关闭后由下一次原生绘制恢复真实探索状态。

“未到访传送点”按原生传送菜单许可统一判定，不维护目的地 ID 白名单或固定点位数量。
在原生地图显示构建前自动枚举当前地区的传送状态，
要求最终 `registered && !blocked`；有所属 area 时，该分组也必须属于当前地区且最终未被禁用。
满足条件的未到访点可临时显示，必要时同时显示 area 分组，不要求真实到访锚点或该分组此前已经发现。
检查基于已经完成的原生状态脚本结果，不把登记期间尚未施加灰态的中间状态视为最终许可。
只接受三个已经确认先执行状态脚本的原生调用来源，以及即时刷新中精确包围本次显示构建的线程局部许可。
场景初始化及未知调用来源保持原生行为，不能把尚未重新计算的缓存当作当前剧情许可。
重复、未知或不一致的数据不处理；点及分组只临时改变菜单缓存中的可见状态，不写真实到访旗标。
游戏后续的静态条件、内部点和特殊标识过滤仍参与构建，已登记并不保证最终一定有玩家可选项目。
不解除原生最终灰态，不扩大当前地区枚举范围，保留原生确认及传送前后脚本。
这一语义不等于完整剧情可达判断：真实到访限制、物理门锁及事件入口之间没有统一的无副作用判定，
因此显示出来的未到访点可能越过入口剧情、物理障碍或迷宫层级。
地图重建后重新计算，不保留自己的到访历史。
实际行走和传送仍可能按游戏机制产生真实进度。

绘制／输入线程只提交传送开关请求，不从 `Present` 调用游戏脚本或操作原生菜单对象。
原生区域地图、全地点列表与城镇子列表的安全浏览调用链消费刷新请求，重新生成菜单状态与列表；
同一次刷新使用固定的目标开关，连续切换时以后续最新请求为准。确认窗口、地图转场等阶段先保留请求，
返回浏览阶段后自动应用，面板区分请求状态与已应用状态。

刷新保留地图镜头和缩放；若原选中项因关闭辅助而消失，使用原生逻辑重新选取有效地点，
避免留下可确认的旧选项。列表滚动位置可能回到默认值。此流程仍需要按游戏内测试清单验证，
纯逻辑测试不能证明所有菜单状态和剧情组合都已覆盖。
重算后，当前子列表或完整传送清单可以合法为空。适配层区分空清单与结构校验失败，
在调用会读取第一个项目的原生列表构建函数之前，改用原生状态 17 的退出动画关闭地图；
此时保持功能可用，不执行传送，也不在菜单更新调用栈内销毁菜单对象。
普通地图浏览可以从空显示数组开始处理开关；地点列表和子列表则仍要求原列表有效且非空。

原生编译器对内部调用采用了比标准 x64 ABI 更强的寄存器保留假设。
地图参数桥保存所有易失寄存器，仅替换 XMM3 的低 32 位；传送显示构建及菜单浏览桥在原函数之前执行辅助逻辑，
恢复全部易失寄存器、XMM0～5、RFLAGS 与原始参数后，再进入原生函数。
Windows 回归测试直接链接生产汇编，故意破坏辅助回调的寄存器，核对传参、返回态、栈对齐和边界。
功能入口冲突会停用对应辅助，并通过面板和日志报告，不覆盖未知挂钩。

适用范围与待验证项目见 [探索辅助测试指南](EXPLORATION_TESTING.md)。

## 面板提示与用语

宝箱状态统一使用“已开／未开”，差额统一为“剩余未开”，当前游玩轮次统一称为“本周目”。
图例、全局与地区计数、清单和快捷键说明使用相同用语；术语调整不改变位标志、统计或筛选语义。
快捷键与动作分列对齐；顶部选择项统一称为“显示模式”，切换动作称为“切换模式”。
探索行将名称与状态直接连接，例如“地图全显：已关闭”，不再为状态预留独立宽列。
对应组合键使用与宝箱快捷键一致的高亮颜色，并与上方右侧按键列对齐；键盘与手柄采用同一对齐规则。
主面板直接显示快捷键与动作。地图收集清单底部使用三列两行：第一行放置“切换模式”“全部/遗漏”“收起清单”，第二行放置“上一页”“下一页”。
页码位于顶部“已完成 … 张地图／剩余未开 …”统计行的最右侧，与清单内容区右边缘对齐；等待游戏数据时不显示尚无依据的页码。
主面板宽度按实际文字及当前输入方式测量，减少固定宽度产生的右侧留白；测量仍需容纳两组地区计数、完整手柄组合、探索名称与状态，并保留按键列的对齐。
清单按最长地图路径、计数列、顶部统计与完整快捷键测量所需宽度，减少“大地图 / 地点”列的多余留白；可用窗口较窄时，保留长路径换行，不能仅为缩短列宽而截断地图名称。
每个操作单元分别绘制高亮按键与普通动作文字；手柄组合逐项带上 View 前缀，不依赖标题或共享缩写补全。清单与主面板使用相同的按键高亮颜色。
底部只保留一句简短说明；等待应用和功能不可用等状态使用同一提示区域，详细功能边界由文档说明。
布局仍跟随输入设备热切换，按键绑定和动作分发保持原有逻辑。

## 面板分辨率缩放

每帧读取交换链后缓冲尺寸，缩放比例取 `min(宽度 / 1920, 高度 / 1080)`。
面板继续使用逻辑坐标布局，ImGui 的 `DisplaySize` 设为实际尺寸除以比例，`DisplayFramebufferScale` 设为该比例。
项目固定版本的 DX11 后端同步缩放视口和裁剪区域，并按该密度生成字体，因此不必逐个修改面板尺寸与间距。
读取尺寸后立即释放后缓冲引用；分辨率切换时重新计算，不重复累乘样式数值。
该设置只影响 Mod 面板，游戏原生地图的位置和缩放仍由游戏负责。

## 手柄和设备切换

输入接入点在游戏自身的 XInputGetState 导入槽，继续调用原目标以保留 Steam Input 映射。
每个手柄槽独立维护状态。View 作为修饰键时，组合不传给游戏；先松开 View 后仍按住的功能键继续被屏蔽到真正释放。
单独 View 在松开时补发一次，并维护输出状态的数据包序号。

实际按键活动及死区外的有效模拟输入切换到手柄提示；键盘和真实鼠标消息切回键鼠提示。
后台不执行 Mod 动作，重连／回到前台需松开控制后重新进入可用状态。
Mod 不拦截系统全局快捷键，因此避开会与 Xbox 窗口冲突的 View + Menu，使用 View + RS 暂停。

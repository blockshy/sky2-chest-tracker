## 模块职责

| 模块 | 职责 |
| --- | --- |
| `tracker`、`core`、`progress` | EXE 校验、宝箱图标、当前存档旗标与地图统计 |
| `overlay`、`ui_text`、`game_language` | 绘制、输入提示、八语文字与字体 |
| `input_bridge`、`controller_logic` | 游戏实际 XInput 路径的观察与组合键边沿处理 |

| `revisit_journal`、`runtime_files` | 当前行程、历史返程记录、文件归属与有界日志 |

## 入口与版本边界

独立版通过根目录 XInput 代理启动，ASI 版通过 Loader 的 `InitializeASI` 启动；两者使用同一组功能对象。进程内保护避免同一宝箱 Mod 被重复初始化。Loader 不负责协调其他插件的挂钩或输入行为。

初始化先核对完整 EXE SHA-256，再核对内存中的函数签名、虚表及特定调用点。未知版本、签名冲突或对象读取失败时停止相应功能，不猜测相近地址。资源目录内嵌的 EXE 指纹还必须与 `game_version.h` 一致。

Ver.1.05 的场景管理器字段集中在 `field_layout.h`。场景根节点、当前／待加载场景、事件盒数组、Player、地图管理器和加载描述均已重新定位。菜单、Player 内的 Actor、Actor 坐标与存档数据是不同对象，不能统一减去 8 字节。原生加载状态编号也发生变化，Mod 仍调用完整加载 API，不直接构造原生状态队列。

## 宝箱与探索

宝箱身份和地图归属来自本机表格与场景资源。正式目录为 566 个宝箱，排除五条不计入正式目标的记录；生成时校验数量、键和定位。标志位区分本周目、发现与继承记录，特殊宝箱使用表内覆盖值。

统计只读取当前存档，继承记录包含当前周目新增记录，不跨存档栏位合并。地图显示逻辑不写入开箱、发现或继承旗标；真实开箱仍由游戏处理。

地图全显只作用于已加载／已选地图的直接分块绘制，递归节点保留原生透明度。传送点辅助在原生规则计算完成后更新临时显示缓存，保留剧情灰态、入口变体、确认窗口和传送前后脚本，不写真实到访标记。

## 传送与返程

界面只提出值对象请求。游戏线程重新读取当前场景、章节、Player、地图菜单与临时结果，验证请求身份和时效，再沿原生关图、结果消费、完整换图路径提交。绘制线程不直接执行换图或写角色坐标。

坐标和朝向取自实时 Player／Actor 关系，精确返程将场景、XYZ 和朝向交给原生完整加载 API。函数返回不等于到达：必须观察加载繁忙位、场景及位置稳定后才能确认成功。等待、拒绝、过期和未确认到达具有不同状态，不能丢失待清理的原生结果。

全传送策略解除清单目的地的剧情准入限制，仍执行对象身份、章节、稳定浏览、加载繁忙和请求时效检查。剧情限制策略保留作为独立开发对照。前往不同剧情进度的场景仍可能触发原生事件与自动保存。

特殊保护只允许已核对的调用点和对象：宝箱保护核对 `system.TBoxProcess`、宝箱行、参数和返回地址；森林保护核对当前场景登记的指定事件盒与本次 VM 临时参数，不全局屏蔽事件，不补写剧情旗标。

MASM 跳板负责保留原生调用额外要求的寄存器、标志与展开信息。修改挂钩位置、调用约定或栈槽时必须同时核对真实指令和 ABI 测试。

## 本机记录与隔离

独立版数据位于 `Sky2ChestTracker/`，ASI 位于 `plugins/Sky2ChestTracker/`，互不导入。新构建使用 `revisit-return-26290169.dat` 和 `revisit-history-26290169/`；历史构建文件保持原始字节与指纹，不跨 EXE 执行。

返程记录带版本、EXE 指纹及完整性校验，但不绑定存档栏位，不保存完整游戏进度。当前记录与历史记录分开维护，失败时保留可恢复数据；不能用历史归属白名单放行旧运行版本。

所有额外内存读取有界并处理不可访问内存；异常保护不吞掉原生函数自身的异常。日志限制大小，诊断按变化输出，避免每帧重复记录。

## 验证要求

自动测试覆盖逻辑、ABI、真实生产 helper 的合成对象读取、文件生命周期和 Loader 隔离加载。新版本还需要完整函数及引用目标、RTTI、导入、资源语义和实机日志核验；通过合成测试不能替代玩家实际操作。检查清单见 [测试说明](TESTING.md)。

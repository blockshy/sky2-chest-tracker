# 语言与原生名称

[项目首页](../README.md) · [玩家操作说明](USAGE.md#语言与字体) · [构建指南](BUILDING.md)

0.6.0 的独立版与 ASI 插件版共用游戏全部八种文字语言支持：简体中文、繁体中文、日文、英文、德文、法文、西班牙文、韩文。本页说明实现约定和验证边界；玩家无需运行提取工具，也无需安装额外语言包。

## 自动跟随规则

Mod 读取游戏的**文字语言**，不读取语音语言、Steam 客户端语言或 Windows 语言。玩家在游戏中确认文字语言后，面板、提示和原生地点名称按同一语言显示。

| 原生编号 | 游戏资源代码 | 游戏文字语言 | Mod 语言 |
| --- | --- | --- | --- |
| 0 | `jp` | 日文 | 日文 |
| 1 | `en` | 英文 | 英文 |
| 2 | `de` | 德文 | 德文 |
| 3 | `fr` | 法文 | 法文 |
| 4 | `es` | 西班牙文 | 西班牙文 |
| 5 | `tc` | 繁体中文 | 繁体中文 |
| 6 | `sc` | 简体中文 | 简体中文 |
| 7 | `ko` | 韩文 | 韩文 |

原生编号与 Mod 的 `Language` 枚举不是同一顺序；生成名称数组的固定顺序为 `sc/jp/en/tc/de/fr/es/ko`。编号 `0` 是有效日文，不代表“未初始化”。八种有效游戏语言分别选择自己的完整文案与原生名称，不把繁体转简体或将其他语言合并到英文。指针为空、页面不可读、编号超出 `0..7` 时保留上次成功检测的语言；首次有效检测前沿用默认中文。

## 检测依据与线程

仅在完整 EXE 哈希符合 [兼容版本](INSTALLATION.md#兼容版本) 后启用检测。`InitializeGameLanguage()` 接收已经校验的模块基址；`RefreshGameLanguage()` 在绘制前调用，内部每 250 毫秒最多读取一次，并串行化自身读取操作。

受支持构建的全局设置对象指针位于 RVA `0xC60E50`，对象内 `+0x623A31` 为文本语言，`+0x623A32` 为语音语言。原生选项窗口在 RVA `0x1869C6` 读取文本语言，确认选择后在 `0x186F6C` 写回；资源初始化在 `0x02FA30` 读取该字节并传给资源语言选择函数。原生资源代码表位于 RVA `0xAA5F30`，顺序与上表一致。

这些地址只适用于当前校验通过的 EXE。适配更新时必须重新核验对象布局、原生枚举与资源加载关系，不能只修改允许的文件哈希。运行时通过 `ReadProcessMemory` 只读自身进程并前后核对对象指针，不修改游戏语言、存档或资源。

## 游戏名称来源

构建从玩家自己的游戏目录读取八组表包：

| Mod 语言 | 原生表包 |
| --- | --- |
| 简体中文 | `pac/steam/table_sc.pac` |
| 日文 | `pac/steam/table.pac` |
| 英文 | `pac/steam/table_en.pac` |
| 繁体中文 | `pac/steam/table_tc.pac` |
| 德文 | `pac/steam/table_de.pac` |
| 法文 | `pac/steam/table_fr.pac` |
| 西班牙文 | `pac/steam/table_es.pac` |
| 韩文 | `pac/steam/table_ko.pac` |

地点与地图名称来自 `t_place.tbl`，传送显示名称来自 `t_mapjump.tbl`。遇到传送表尚保留内部名称的行，使用同一原生地点 ID、场景对应的正式地点表名称。利贝尔方舟的地区名取自 `t_notemenu.tbl` 的原生手册地区分类，避免把地点表中的调试名自行翻译成玩家名称。

以下规则保持名称与实际游戏对象一致：

- 使用原始地点／传送 ID、场景和稳定地图 key 关联，不根据译文相似度猜测地点。
- 多语言显示名称不会增加目的地、开放内部入口、合并同名地图或重编号宝箱。
- 原始地区名、地图名和地点名保留原生用词；路径分隔符及 Mod 自有动作可本地化。
- 普通四塔与异空间各自保留原生身份；不能用一种语言的同名字符串作为唯一键。
- 对缺失、有歧义或越界的原生资源生成失败，不静默编造译名。
- “返回记录的出发点”等属于 Mod 自有动作，使用界面文案翻译；返程保存的场景、位置、朝向和目标身份不受语言切换影响。

`tools/localized_game_names.py` 供现有地图、传送生成器共用。产物 `map_localization.h`、`travel_localization.h` 作为旁路名称表编入 DLL／ASI，`maps.json`、`travel_localization.json` 保留来源以供本地核对。原始游戏表和生成目录均由 Git 忽略，不作为额外玩家安装文件分发。

## 界面与字体

Mod 自有提示集中在 `native/ui_text.h`，游戏名称通过 `native/localized_names.h` 获取。窗口 ID、地图 key、目的地 ID 与导航状态独立于翻译文本；八种语言保持相同快捷键与操作语义。

字体使用玩家 Windows 已安装的拉丁、中日韩字库，不从游戏提取字体，也不随包分发系统字体。中文、日文或韩文出现方框、缺字或字体缺失提示时，应安装相应的 Windows 补充字体后重新启动游戏。缺少字体不会擅自改变所选文字语言。

## 验证边界

无游戏的测试可检查原生枚举映射、异常状态保留、界面翻译选择及格式占位符；Windows 用例使用私有模拟内存验证空指针、地址溢出与不可读页面。资源测试按原生身份和来源核对八语条目；这些检查不等于游戏内语言切换已经通过。

实机检查应分别确认八种文字语言下的主面板、宝箱清单、传送清单和返程提示，核对原生地图与 Mod 地点名称，并检查键盘／手柄提示、长名称换行及切换后的清单位置。语音语言单独改变时，Mod 文字应保持不变。各次构建已完成和待完成的检查以 [测试说明](TESTING.md) 为准。
